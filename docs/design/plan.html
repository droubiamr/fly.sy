fly.sy · Redesign plan · 1 October 2026

Answer first, details on tap

The site already has the right information. It is hard to find because every page is a column of identical white cards and small grey text, so nothing stands out. This plan reorganises it around one idea: show the answer first, group what repeats, and keep the fine print one tap away.

Every fact, source and date stays on the site, and so does every address search engines know. Updated after your answers: the look changes too, so the mockups below show the new structure in today’s colours, and three new visual directions are on their own page. Nothing on the site has been changed yet.

Live on fly.sy now

About 1 in 3 pages is failing for visitors and crawlers

On 1 October I requested 12 pages on fly.sy. Four came back with Cloudflare error 1102 (the server ran out of CPU time), and every page that did load reported x-nextjs-cache: MISS. The site is built so pre-rendered pages come from a cache. The live deploy is skipping that cache, so each visit redraws the world map on the server and some run out of time. Google, Bing and AI crawlers get these errors too, and repeated server errors make search engines crawl less and drop pages.

The likely fix is a setting, not code. In Cloudflare: Workers & Pages → fly-sy → Settings → Build. Set the build command to npx opennextjs-cloudflare build and the deploy command to npx opennextjs-cloudflare deploy. The deploy step is what copies the cache in; plain wrangler deploy skips it. If you deploy from your computer instead, use npm run deploy. After you redeploy I’ll check the live site again.

What I found

Why it feels crowded

  • 7×

    The same headline over and over

    On Türkiye → Damascus, “Fly · Damascus airport → Damascus” is printed seven times. What actually differs, the airline and the city, sits in small grey text underneath.

  • 13px

    The answer is a grey sentence

    The fastest route is a line of small grey text above the map. The routes themselves start below the first screen on a phone.

  • 14

    Font sizes that are almost the same

    From 10.5px to 24px with most of them between 11 and 15. When every size is close, nothing reads as more important.

  • 1 box

    Every kind of thing looks alike

    Routes, crossings, papers, airlines and FAQs all use the same white rounded card. The eye has nowhere to land.

  • 6 of 6

    You read every case to find yours

    The papers page shows air and land for all three passports at once. You only ever need one of the six. Each fact also carries its own “Source: … · checked …” line, which doubles the text.

  • 672px

    Desktop is a stretched phone

    A narrow column in the middle of a 1440px screen, with the phone’s floating tab bar sitting on top of the routes.

The approach

Six rules every page follows

  1. One answer per screen, in the biggest type on itThe first thing you see on the route page is how to get there and how long it takes.
  2. Group what repeatsFlights are grouped by the airport they land at. Seven cards become one row you can open.
  3. Show the exception, not the norm“Operating” becomes a small green dot. Closed, unknown and “Syrians only” get a coloured label with an icon, so they stand out.
  4. Fine print one tap awaySource, confidence and date move into a small badge that opens on tap. Nothing is removed; it just stops repeating under every line.
  5. Each kind of information gets its own shapeThe answer is a highlighted panel, options are an accordion, flights are compact rows, papers are a checklist, crossings are a status list.
  6. Phone and desktop each get a real layoutPhone keeps the bottom tabs. Desktop gets a top bar and two columns, with the map beside the answer.

Search engines and AI assistants

The redesign must not cost a single ranking

The site is already in good shape here: every page is pre-rendered, with its own address per language, canonical and hreflang tags, structured data and a full sitemap. The redesign changes how pages look, not what they say or where they live.

Protected

  • Same addresses. Tab names change; URLs don’t. /crossings stays /crossings even when the tab says Borders. If an address ever has to move, it gets a permanent (301) redirect.
  • Hidden is not missing. Closed groups, tabs and source badges keep their text in the HTML. Google and AI crawlers still read every flight, source and date.
  • Same titles, descriptions and headings. Same canonical, hreflang and structured data on every page.
  • Internal links stay. The country and city links move from chips to a quiet list at the bottom of each route page. They stay on the page.
  • No slower. Fonts are self-hosted through Next.js and split by script. Search code loads only when it’s opened. Logos and map have fixed sizes, so nothing jumps. Lighthouse scores before and after each step; no step may make them worse.
  • Checked every time. The existing smoke test runs before each push. It covers status, canonical, hreflang, structured data, redirects and 404s on every sitemap address.

Added

  • A one-line answer on every route page. For example: “The fastest way from Türkiye to Damascus is to fly to Damascus airport, about 2 h 40 door to door. Checked 30 September 2026.” Google snippets and AI assistants quote sentences like this.
  • /llms.txt: a plain-text guide for AI assistants. It covers what fly.sy is, how to read the confidence levels, and links to every key page and the data.
  • Open data files. Routes, crossings, airports, airlines and papers as JSON, with source, confidence and date on every record (CC BY-SA). They are listed in the Dataset markup, so agents read exact facts instead of guessing from the page.
  • Honest freshness per page. Each airport, crossing and airline page gets its own “last modified” date from when its facts were checked, instead of one date for the whole site.
  • More structured data, only for what’s visible. FAQPage on About, and the ways as an ItemList on route pages.
  • Bing, which feeds ChatGPT search and Copilot. Verify fly.sy in Bing Webmaster Tools and turn on Cloudflare Crawler Hints, so Bing hears about updates the same day. Both are dashboard steps, no code.

AI crawler access is already open: robots.txt allows everyone. I sent requests with the user agents of GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, PerplexityBot, Applebot and Googlebot. All got pages when error 1102 didn’t hit. Keep Cloudflare’s “Block AI bots” switch off.
