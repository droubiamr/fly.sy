# fly.sy audit, October 2026

Speed, SEO and AI-assistant visibility, audited on 1–2 October 2026. Six auditors (data flow, performance, technical SEO,
AI assistants, cost and operations, content model) produced 103 findings. Three skeptics checked each one for evidence,
priority and fix; 99 held. The plan below is what survived, with the skeptics' corrections applied.

The audit read commit `1cbc745`. The five commits after it, up to `aedd935`, were taken into account: they fixed the
About-page FAQ on direct flights from Europe and added `worker.ts`, which serves prerendered pages, prefetches and
`/api/track` without starting Next. They also confirm the site runs on Workers Free.

General lessons from this audit, the ones that apply to any site, live in the `seo-ai-visibility` skill
(`droubiamr/claude-skills`), not here.

## 1. Verdict on the architecture

The architecture is right for the goals and should stay. All public pages are prerendered from git-tracked `data/*.json`. They are served as static files on Cloudflare Workers. D1 is used only for reports, analytics and admin.

The measurements support this:
- All 338 pages are static. Time to first byte is about 0.2–0.3 s.
- The site makes zero third-party requests.
- On route pages the largest visible element (LCP) is the answer sentence, and layout shift is 0.
- hreflang, canonicals, sitemap and JSON-LD are clean.
- All AI crawlers are allowed.
- `llms.txt`, `llms-full.txt` and `/data/*.json` are generated from the same data, so they cannot drift from the pages.

The weaknesses are not in the stack. There are three of them:
1. **A few AI-facing strings state wrong or misleading facts.** Examples are airline snippets, the "overland" labels in `llms-full.txt`, and the passport-blind route answers.
2. **Data that grows does not yet flow into the pages that rank.** This covers community reports, news, document check dates and crossing aliases.
3. **Some cheap operational safety nets are missing.** There is no backup, no throttle on public writes, no logs and no cache headers.

None of these needs a stack change. In particular, do not move to R2/KV revalidation or edge HTML caching now.

## 2. Corrections to the earlier answer

1. **"Community reports never reach search engines or AI" was wrong.** Approved reports already appear on `/reports` and `/en/reports`. Those pages are rendered per request, indexable, in the sitemap and linked from `llms.txt`. What reports do not reach:
   - the crossing and airport pages (`entry-page.tsx:70` reads only `reports.seed.json`)
   - `llms-full.txt`
   - `/data`
   - the sitemap `lastmod`

   The live `/en/reports` shows only the 3 seed reports, so **nothing is lost today**. The impact is medium, and it should be fixed before the first real report is approved.
2. **"Get into Bing" still holds, with three changes.**
   - "ChatGPT leans heavily on Bing" is not proven. OpenAI runs its own OAI-SearchBot. Bing is still worth it for Copilot, DuckDuckGo, Yahoo and Ecosia.
   - **Crawler Hints will probably do nothing.** It fires on CDN cache misses, and fly.sy's HTML comes from the Worker with no `cf-cache-status` header.
   - **The Google verification file redirects.** `/google19d367ed05691ede.html` returns a 307 to `/google19d367ed05691ede`. Re-verify Google Search Console by DNS.
3. **"Two Worker requests per page view, so about 50k views/day on Free" was wrong.** A phone landing triggers about 10 or more Worker requests: the HTML, the track POST, link prefetches, icons and the manifest. Commit `ef82124` measured about 10 per click. That puts the Free cap of 100k requests/day at roughly **7–10k landings/day**. When the cap is hit, every page, crawlers included, gets error 1027 until 00:00 UTC. D1 Free allows about 25k tracked views/day, because each view writes 4 rows (the row plus 3 indexes).
4. **"HTML is not edge-cached" holds, but two details were off.**
   - Production does not send `x-nextjs-cache: HIT` at all. It sends `x-nextjs-prerender: 1`.
   - Zone Cache Rules cannot cache HTML the Worker generates. The only lever is Workers Cache, which would also start billing the static-asset requests that are free today.

   Leave it as is.
5. **"page_views grows without bound" holds, but it is a *later* item, not *soon*.** The 13-month cutoff deletes nothing before about 2027-10-23. The `worker.ts` entry on main now makes a `scheduled()` cleanup handler easy to add when it is needed.
6. **"Map SVG is sent twice" was refuted.** Brotli and zstd compress the duplicate copy down to about 0.1 KB on the wire. The real cost is the amount of map geometry: Romania and UAE frames load the detailed 50m atlas (see Now #13).

## 4. Don't do

- **Don't hide the six EU-group origin pages.** That means no noindex, no removal from the sitemap, and no canonical pointing to a nonexistent `/from/europe`. Fix them with data instead (Now #6).
- **Don't switch to an R2/KV incremental cache with `revalidatePath`, and don't fetch reports client-side.** The first reopens the 1102 and cache-key risk behind the 16.3.7 pin. The second hides reports from crawlers.
- **Don't call `revalidatePath` on public paths.** With the read-only static-assets cache it does nothing, even though it looks like it works.
- **Don't read D1 at request time on entry pages.**
- **Don't enable Workers Cache on Free, and don't add Cache Rules for HTML.** Cloudflare's cache ignores `Vary: rsc`, so it could serve RSC payloads to HTML requests.
- **Don't serve the map as an `<img>`, and don't cap or drop journeys on route pages.**
- **Don't turn off prefetch globally or build a hover-prefetch wrapper.** `worker.ts` already makes prefetch requests cheap.
- **Don't enable `skipTrailingSlashRedirect`.** Two-hop 308s are harmless.
- **Bing:** don't use a `BingSiteAuth.xml` file (the proxy 404s it) and don't add an `msvalidate` meta tag (it forces a rebuild of every page). Use the GSC import or DNS instead. Don't rely on Crawler Hints.
- **Don't replace the JSON casts with `satisfies`** (TS1360 on valid data). **Don't add a guard that throws when `data.ts` loads** (it would break every cold start).
- **Don't automatically downgrade confidence by age, and don't backfill `seen` dates from `meta.updated`.**
- **Don't create per-nationality pages, a `rules.json` of military-service or expired-passport rules, or a live departures board without dated official sources.**
- **Don't commit submitter notes to the public repo before the form carries licence consent.**
- **Don't add region-targeted hreflang tags, and don't migrate off .sy now.** Measure country impressions first.
- **Don't treat a 60/60 rate limiter as enough** against D1 quota exhaustion.
- **Don't exact-pin `@opennextjs/cloudflare`.**
- **Don't schedule daily rebuilds while report volume is about zero.**
- **Don't expect Google FAQ rich results.** Google shows them only for government and health sites. The FAQ is worth doing for AI assistants.
